# OUEM 統合ロードマップ v0.2 — 中核の確立と段階的な一般化（レビュー草案）

- **基準日**：2026-11-21（JST）
- **状態**：**REVIEW DRAFT**。本書の開発の基本方針と当面の優先順位はユーザーとの議論で採用済み。以下の各マイルストーンの詳細な出口条件はレビュー案であり、個別の実装・実行・正式受入を承認するものではない。
- **役割**：目標、現在地、優先順位、次の区切り、将来に付加する機能を示す。実装仕様・実験数値・ソース適格性・契約・Acceptanceを複製しない。
- **履歴**：[v0.1](OUEM_Integrated_Roadmap_v0.1.md)は当初の提案と2026-11-14/19/20時点の判断を保持する。本書はその逐条追記ではなく、現時点の開発方針に適した構成へ再整理したもの。

## 1. 目的

OUEM（Open Urban Environment Model）は、オープンデータと既存OSSを活用して都市の地形・建物・樹冠を3Dで統合し、樹木の都市環境機能を広域かつ再現可能に評価できる基盤を目指す。初期の重点は**日射・日陰**と**歩行者視点の樹冠視認**であり、解釈可能なGIS成果を通じて、将来のグリーンインフラ評価・自治体の緑地施策等へつなげる。

全国の元データをあらかじめ一括整備すること、詳細3D形状の生成そのもの、独自の環境解析エンジンの再実装は目的ではない。目的と上位のデータ・解析設計は[正式Concept & Architecture v0.4](../OUEM_Concept_Architecture_v0.4.md)を参照する。

## 2. 開発を通じた共通原則

**中核を小さく成立させ、実例に基づいて一般化し、必要な機能を段階的に付加する。**

これは開発初期から実践してきた方向性を明文化するもので、既に採用済みの[Development Principles v0.1](../OUEM_Development_Principles_v0.1.md)の反復的な探索・安定化（P2）、最小十分な複雑さ（P3）、責任分界と再利用（P4）を具体化する。新しい万能基盤やプラグインシステムを先に実装する義務は生じない。

1. **OSS-first・目的優先**：VoxCity等の公開機能を優先し、評価用途が必要とする最小限のAdapter・補助処理のみを追加する。全APIの網羅を成果としない。
2. **地域から一般化**：固定した一地域での実証 → 別地域での条件・失敗の把握 → 必要な共通化・安定化、を反復する。地域ごとの専用コードを増殖させない。
3. **共通の意味を保ち、入出力を拡張可能にする**：Raw → Native → Standard → Adapterの責任分界、Observed/Estimated・Primary/Derivedの区別、水平存在・判定可能域・高さ・絶対Z・TREE占有の区別を維持する。意味と責任分界を優先して安定させ、具体的な形式や抽象化は実例に応じて成熟させる。
4. **後付け拡張を許すが、互換性は仮定しない**：GSI点群由来の樹冠入力、GPUによる日陰・日照時間、追加の視認指標等は、需要・資源・入力証拠が整った段階で接続する。異なるソース・バックエンド・指標の同等性は別途検証する。
5. **技術QAは常時継続**：欠測・UNKNOWN、有効0、格子/CRS/鉛直基準、幾何・建物優先、観測点/D0、境界・halo、数値・GIS一致、来歴・再現性・失敗時の安全性を、開発中の必要な範囲で確認する。これは独立実測に基づく科学的精度検証の代替ではない。

## 3. 現在地と実際の進め方

| マイルストーン | 2026-11-21時点の根拠に基づく現在地 | 次の扱い |
| --- | --- | --- |
| **M0** 限定技術基盤 | 狛江市等の既存の限定E2E・GIS・詳細LoD2 PoCは区切り済み | 履歴と回帰QAを保全 |
| **M1** 樹冠3D | 狛江市の完全有効な固定Meta CHMv2入力で、既存TREE全配列との一致を確認。M1全体・Canopy Standardは未完了 | **最優先**：国立市で限定的地域一般化 |
| **M2** 環境評価 | 狛江市の固定CPU B1/B2について**限定技術到達済み**。一般用途・科学精度・正式受入は未確認 | 現行CPU技術を再利用。追加指標は必要時 |
| **M3** 科学的検証 | 独立実測による精度・適用限界の本格検証は未実施 | 大規模な測定・検証は開発後期 |
| **M4** 広域化 | 国立市2kmデータ事前調査あり。建物統合を含む広域E2Eは未成立 | **M1と並行**して準備、次に小領域→2km級→自治体全域級 |
| **M5** 社会実装 | 将来目標 | 検証・権利・用途に即した適格性を整える |

**実際の優先順序**：**M1第2段階とM4の準備を並行** → 国立市の限定モデル・解析 → M4の段階的広域化 → 成熟した用途に対するM3の独立検証 → 適切な範囲でM5の社会実装。M2の追加機能や新規樹冠ソースは必要性と資源に応じて途中で付加できる。

M0〜M5は**成果の識別子であって、着手を番号順に強制する工程ではない**。本書のRoadmap M1は、別リポジトリの樹冠セグメンテーション側のM1や過去の実装A1–A3とは異なる。

## 4. マイルストーンと区切り

### M0 — 限定的な技術基盤

**区切り済み（既存の限定範囲）**。狛江市等の地形・建物・推定樹冠、VoxCity B1/B2技術E2E、GIS成果、詳細LoD2の別PoCを証拠と限界ごと保存する。旧データを新たに「再受入」しない。正式な全ソース受入・科学的精度・全国適用は含まれない。

### M1 — 樹冠3Dモデルの地域一般化

**次の目標：第2段階「Meta CHMv2経路の限定的な地域一般化」**。既に成立した狛江市の固定入力・固定エンジンによるTREE再生成に続き、**同一の平面直角座標系EPSG:6677の国立市**の限定領域へ、同じ意味・規則の経路を移植する。

**第2段階の出口案**：Meta CHMv2に基づくモデル上の樹冠存在/不存在/UNKNOWN、CHM・DEMの高さ有効性、鉛直基準・絶対上下端Z、格子・来歴を区別して扱う。入力不足時は安全に停止し、有効な条件でTREEを再現可能に構築できることを国立市の実データとQAで示す。狛江市の既存再現性を損なわない。最小限のNative/Standard/Adapterの意味・責任分界を維持し、具体的な形式の正式確定は地域展開の証拠を踏まえて判断する（**C2方針**）。

**境界**：最初の国立市試験は**樹冠の3D構築を中心**とし、建物との都市モデル統合・広域環境解析はM4へ引き渡す。第2段階の到達はM1の全構想・正式Canopy Standard/Acceptance・現地の樹冠精度の成立ではない。GSI点群からのCHM/樹冠生産、独自セグメンテーション、異なるEPSG系、必須の2D樹冠ポリゴン/3Dメッシュはこの出口に含めない。

### M2 — 樹冠の環境機能を評価する技術

**固定CPU条件の限定技術出口は達成済み**。狛江市の保存済みモデルに対して、VoxCity 1.7.0 CPUを用いた次の指標の定義・入力条件・観測点・GIS成果・未検証条件を記録した。

- **B1**：人工太陽条件における**瞬間水平面直達日射強度（W/m²）**と、同条件のNo-Canopy − Currentによるモデル上の日射低減。
- **B2**：**CPU weighted first-TREE view index（無次元）**。写真式緑視率や二値樹冠ヒット率ではない。

既存証拠を[限定技術終了記録](../status/M2_LIMITED_TECHNICAL_EXIT_CLOSEOUT.md)から参照する。固定領域外の遮蔽物、物理的な歩行者観測高さ、実気象、科学的精度、一般的なCPU/GPU指標同等性は未検証である。

**将来の主要な追加指標は日陰・日照時間**。期間積算日射、用途に適した視認指標、GPU機能等も必要に応じて評価する。GPU経路は魅力的だが、インストールだけで既存CPUの計算と同等になるとは限らない。指標・条件・観測位置・計算領域・出力意味・再現性を個別に確認する。これらの追加実装を**M1第2段階やM4着手の必須条件にはしない**。

### M3 — 科学的妥当性・不確実性・適用限界

**本格的な独立実測は後期**。成熟した樹冠モデル・日射/日陰・樹冠視認について、比較可能な独立参照データや必要に応じた現地測定を設計し、精度、誤差要因、不確実性、用途ごとの適用限界を明らかにする。高精度をあらかじめ仮定したり、全地域・全季節の一律保証を求めたりしない。

参照データの入手可能性・時点・品質・権利・費用は未確定。低コストの机上調査や必要な限定的検証は先行してよいが、大規模調査をM1/M4の技術開発の前提にしない。将来の日陰形成時間はその時間指標に対応する参照、視認は採用指標との対応を明示した参照で評価する。現在のB1瞬間日射と日陰時間、現在のB2指標と写真式緑視率を同一視しない。

**出口を二つに分ける**：検証計画・実施範囲・未実施理由を整理して研究上の検討を区切ることと、独立した証拠に基づき**特定用途の科学的妥当性が確認されること**は異なる。未確認の項目はNOT_VERIFIEDのまま残す。

### M4 — 都市モデル・環境解析の広域化

**国立市を最初の地域一般化・広域化の対象とする**。M1の樹冠経路を受け取り、地形・建物を統合し、既存のCPU B1/B2解析を小領域から2km級、自治体全域級へ段階的に拡張する。データ被覆・LoD・絶対Z/CRS・権利、計算域と評価ROI/context、境界、欠測、外部遮蔽物、処理時間・メモリ、GIS成果を扱う。

**途中の技術的区切り**：国立市の限定モデルから2km級まで、再現可能な入力準備・3D統合・選定環境解析を段階的に確認する。既存[国立市2km調査](OUEM_Kunitachi_Data_Source_Preflight_v0.1.md)はDEM/CHMの被覆と一部建物データを示すが、2kmの全建物LoD2充足や統合モデルの成立を示さない。

**M4全体の出口案**：少なくとも一つの自治体全域を**処理対象**として、入力準備から3D統合、選定指標の評価・GIS成果までの広域処理と移植性を検証する。行政界、ソース被覆、計算領域、評価可能域、対象外・データ不足・処理不能域を区別する。全域を処理対象としたことを「全域に欠落のない定量評価ができた」と言い換えない。

M4準備では、[一般化監査](OUEM_Data_Pipeline_Generalization_Audit_v0.1.md)のG01読取専用preflightを最初の候補とし、G02建物Source-H選択、G03 Terrain追加入力は実要件に応じた別課題とする。これらの実装・取得をロードマップだけで許可しない。全国一括計算や全建物のLoD2必須化は行わない。

### M5 — 全国オンデマンド展開と社会実装

地域・データ・指標・用途の適用条件を利用者が理解し、再現可能な3D都市モデルとGIS環境評価を第三者が利用できる状態を目指す。データ・OSS・派生成果の利用権利、再現手順、実行資源、欠測、科学的な適用限界を明示し、自治体の緑地施策等で試用・改善する。

**出口案**：宣言した適用範囲における適切な利用可能性と、用途に必要な技術・科学・契約・権利上の証拠が揃うこと。未検証の環境便益を実測済み・精度保証済みとして提供しない。すべての地域で一律の精度・機能を保証することは求めない。

## 5. 後から付加する機能

| 拡張候補 | 将来の意味 | 当面の必須依存か |
| --- | --- | --- |
| GSI点群・樹冠セグメンテーション | Meta CHMv2に続く別の樹冠入力プロファイル。別リポジトリとのhandoffは独立審査 | **いいえ** |
| GPU日陰・日照時間 | 初期CPU日射に加わる、目的上重要な時間指標 | **いいえ** |
| GPU/別方式の樹冠視認・追加環境指標 | 用途に適した計算定義・性能を選択する拡張 | **いいえ** |
| 2D樹冠ポリゴン・3Dメッシュ | GIS/可視化/他モデル向け任意の派生成果 | **いいえ** |
| 他CRS/入力ソース/全国的運用 | 地域展開の実例に合わせて増やす対応プロファイル | **いいえ** |

この表は着手を承認するものではない。追加時には、既存の共通モデル・OSS・GIS出力を再利用しつつ、入力の意味・権利・品質と新しい計算結果の意味・再現性を検証する。

## 6. 区切りの判定・運用

**四軸を混同しない**：(1) 技術的到達、(2) 科学的妥当性、(3) 正式Contract/Acceptance、(4) 利用権利・適格性。限定技術PASSは他軸のPASSでも、全条件への一般化でもない。

マイルストーンの目標・優先度と重大な設計変更はユーザーが判断する。個別の実装・外部データ取得・実計算・新しい科学的仮定・正式契約・Acceptanceの変更は、それぞれの責任と承認に従う。ロードマップの改定だけでコード、データ、契約、過去の実行結果、正式な受入状態を変更しない。

詳細は責任文書へリンクする。開発中は小さい技術QAを継続し、明らかな幾何・意味上の問題はM3の現地検証を待たず扱う。ロードマップはマイルストーンの区切り、重大な制約の発見、データ/OSS/資源条件の変化に応じて見直し、各PRで全文を改稿しない。
