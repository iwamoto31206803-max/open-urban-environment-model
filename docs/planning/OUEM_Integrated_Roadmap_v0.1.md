# OUEM 統合ロードマップ v0.1 — M0〜M5（レビュー草案）

- **状態**：PROPOSED / REVIEW DRAFT。2026-11-11の議論で**M0〜M5の成果ベースの構成**を選択。個々の完了条件・具体的な作業・予算・期限・新たな科学的条件の承認は**別判断**。
- **GitHub照合基準**：2026-11-11、main `e7f9dbbc836032597df1f60773e7c30279cb83e5`（PR #176マージ後）。既存記録の読み取りに基づく計画提案であり、新規実データ処理・精度検証ではない。
- **目的**：「今どの成果に向かうか、何をもって区切るか、何を後回しにするか」を、User / ChatGPT / Codexが同じ根拠から判断できるようにする。ロードマップは**優先順位と出口の所有元**であり、個別実験の数値・実行手順・Standard・Acceptanceを複製しない。

## 1. 最上位の目的と権限

[Concept & Architecture v0.3](../OUEM_Concept_Architecture_v0.3.md)の目的を維持する（旧[v0.2](../OUEM_Concept_Architecture_v0.2.md)は履歴として保持）。地形・建物・樹冠のデータを日本各地でオンデマンドに3D統合し、人が体感する樹木の環境機能（日射・日陰、樹冠緑視など）を再現可能で解釈可能なGIS成果として評価する。全国データの先行一括整備、詳細3Dモデルの生成そのもの、解析エンジンの自社再実装は目的ではない。

[Development Principles](../OUEM_Development_Principles_v0.1.md)を開発方針の正本、[5モジュール横断レビュー](../reviews/OUEM_VoxCityGML_P1_Architecture_Closeout_20261110.md)を機能・OSS責任分担の参照元とする。Raw → Native → OUEM Standard → Adapterと、**ソース／レイヤーに応じたPrimary・DerivedおよびObserved・Estimatedの独立管理**を維持する。樹冠の解析用ラスタ情報と任意の外部幾何出力の分離はConcept v0.3 §4.3に従う。正式Concept、各Standard／Adapter、過去のAcceptance、実験報告、Deferred Backlogは**それぞれが自分の判断・証拠を所有**する。このロードマップのマージでこれらを変更・承認・追認しない。

M0〜M5は**統合ロードマップ専用の識別子**。過去のPhase A/B、実装工程A1–A3、VoxCityGML PoC-P1、独立`ouem-canopy-segmentation`のM1等とは別体系であり、同じ番号は同じ受入範囲を意味しない。文書内では必要に応じ「Roadmap M1」と明記する。

## 2. M0〜M5：成果、終了条件、対象外

下記の「終了条件」は**提案**であり、新しい正式Acceptanceゲートではない。「技術的な段階の区切り」と「科学的検証／正式受入／利用権利」の状態は分けて記録する。

### M0 — 限定的な技術基盤の確立

**現在地：既存の限定技術実証は区切り済み。** [B1技術Closeout](../status/B1_TECHNICAL_MILESTONE_CLOSEOUT.md)、[B2技術Closeout](../status/B2_TECHNICAL_MILESTONE_CLOSEOUT.md)、[P1詳細LoD2 Closeout](../reviews/OUEM_VoxCityGML_P1_Architecture_Closeout_20261110.md)を根拠とする。

**成果／終了条件**：既存の狛江等の限定入力・固定条件で、Terrain、Building、推定Canopyのモデル構築とVoxCityのB1/B2技術E2Eが記録・再現可能な条件で保全され、詳細LoD2の別PoCも限界とともに閉じている。既存エビデンスを**再受入しない**。M0の完了は完成版Standard Canopy、物理的観測位置、日射・緑視の科学的精度、正式VoxCityGML Adapterを保証しない。

### M1 — 信頼できる樹冠3Dモデルの構築

**中心モジュール：②樹木、①地形、④統合。現在の開発重点。**

**必要な成果（Concept v0.3整合の提案）**：
1. 代表AOIで、ソースプロファイルに応じた**樹冠水平存在情報・モデル判定可能域**を保持し、出典、時点、推論規則、ライセンスとともに説明する。Meta CHMv2の有効正値／0値はモデル上の存在／不存在であり、NoData・範囲外はUNKNOWN。GSI等の推定マスクや原樹冠ポリゴンでは別の根拠を保持する。**モデル判定可能域と独立に調査された生態学的coverageを混同しない**（現地実在性の検証はM3）。
2. 既存Height EnvelopeのHAG/CHM数値・元マスク・DEMと樹冠水平情報を独立管理し、共通GridSpec、互換性を確認した**絶対上端／下端Z**、CRの推定根拠、欠測・鉛直基準・品質・出典を追跡可能にする。元ソースの数値妥当性、モデル存在判定、標高計算妥当性、VoxCityのTREE占有を同一視しない。
3. **解析の主経路：**共通の水平・鉛直情報からAdapterでTREE voxelを再生成する。従来のラスタ/Height Envelope経路と比較可能な限定条件で、engine中心・格子・丸め・建物優先・halo・欠測guardを固定し、構造/意味QAと再実行証拠を記録する。**2Dポリゴンや3Dメッシュを経由させない。**
4. **任意の独立出力：**同じ根拠から2D樹冠ポリゴンを必要時に派生し、その形状・出典・面積・ラスタ往復を独立QAできるようにする。3Dメッシュは具体的用途が生じるまで延期可能。原樹冠ポリゴンが供給されるソースではその原形状とIDを保持し受入時にQAする。
5. 最小のNative/Standard Canopy論理仕様とAdapter境界をレビューする。正式Canopy Standardの採用・データセット受入は[Canopy Standard DRAFT](../OUEM_Standard_Canopy_v0.1_Draft.md)に対する**別の承認**であり、M1の技術実証をもって自動成立しない。

**出口の判定**：根拠付きの水平存在／判定可能域・高さ／絶対上下端・有効性／NoData・GridSpec／来歴から、**対象条件を固定した同じTREE/3D樹冠表現を再現**し、解析可能と不能の範囲を説明できる。幾何出力の有無によってラスタ主経路の限定技術到達を妨げない。必要な水平根拠・鉛直整合・権利が不足すれば、不足対象を**未達／BLOCKED**として明示する。合成試験または暫定モデルの成功だけではM1全体を完了とせず、既に成立した限定成果は保持する。M1到達は現地の樹冠存在・形状精度の科学的独立検証を意味しない。

**今は必須ではない**：単木分割、完成した独自セグメンテーションモデル、全国のポリゴン整備、CHM由来2Dポリゴンの必須中間生成、汎用3D樹冠メッシュ、LiDAR専用新規エンジン、詳細LoD2 Adapterの正式採用。別リポジトリのセグメンテーションは候補供給源であり、前提に固定しない.

### M2 — 樹冠環境機能の再現可能な技術評価

**中心モジュール：⑤環境解析、④統合、②樹木。**

**必要な成果**：M1の対象範囲において、地形・建物・樹冠・観測点の**実際のXYZ、D0、クラス、格子、範囲・外部遮蔽物の条件**を整合させる。B1ではCurrent/No-Canopyから樹冠起源だけを除去して同一条件比較し、日陰と日射の指標・時刻・光学仮定を明示する。B2では主要な樹冠緑視指標を明示し、現在の**暫定CPU weighted first-TREE index**を正式な二値GVIや写真式緑視率と同一視しない。双方で再実行、数値・空間QA、GIS出力、適用限界を記録する。

**出口の判定**：一つの根拠付き3Dシーンから、定義されたB1/B2成果を比較可能な条件で出力でき、シナリオ不変条件・観測点・格子・ソース来歴を検査できる。**技術的再現性・合成幾何に対する整合**は検査するが、これだけで樹冠の実在性、放射量・日陰・緑視の**現地精度**を認証しない。独立参照の可用性調査と科学的評価はM3で実施する。B2主要指標の定義はM2着手時にConcept継承事項と照合して決め、現行暫定指標の名称変更だけでは完了としない。

**今は必須ではない**：年間・全球放射、WBGT・気温改善の物理モデル、樹種別LAD/透過率の校正、独立現地測定に基づく精度認証。これらを未検証として明示することは必須。

### M3 — 科学的妥当性と不確実性の検証

**中心モジュール：⑤環境解析、②樹木、①③④の誤差要因。**

**まず「参照データを得られるか」を調査する**。独立参照データの準備可能性は現時点で未検討であり、その調査自体がM3に属する。あらかじめ検証データが揃っていると仮定しない。

**進め方／必要な成果**：
1. **参照可能性の棚卸し**：樹冠存在・平面境界・上下端、地盤・建物、歩行者位置の日陰／日射、全天球写真・緑視など、検証したい主張ごとに独立参照の候補、時点・範囲・品質・取得条件・ライセンス・費用・実行可能性を調べる。モデルの入力・出力から作った派生量を独立した正解として扱わない。
2. **実行可能な検証の設計**：確保可能な参照に応じて、幾何の独立オラクル、複数ソース比較、感度・分解能・鉛直／観測点／光学パラメータの不確実性分析、必要に応じて新規計測を選ぶ。主張、試験範囲、誤差指標・比較条件、想定限界を実験前に明記する。
3. **証拠に基づく到達判定**：実施できた検証とできなかった検証を分け、指標／対象条件ごとに確認された妥当性・残存不確実性・主張可能範囲を示す。

**重要な二軸の出口**：
- **研究上の検討を区切ること**：参照データの利用可能性、検証方法、実施結果／不実施理由、次の取得条件が記録され、用途と科学的主張の制約が明確である。
- **科学的妥当性を確認できたこと**：独立の適切な参照と事前に定めた条件による証拠が揃った**対象・指標に限る**。参照が不足した場合、研究計画の検討には区切りを付けられても、`scientific_validation=NOT_VERIFIED`相当の未確認状態を保持する。ロードマップ上の「M3の検討終了」を検証成功と表示しない。

**今は必須ではない**：全自治体・全樹種・全季節への一律保証、最初から一つの固定精度閾値を設けること。

### M4 — 市町村全域級への一般化

**中心モジュール：①地形、③建物、④統合。②⑤も対象地域で接続。**

**必要な成果（提案）**：原則として**対象自治体の行政区域全体**を対象とする実行計画と対象範囲を定義し、データの存在・LoD・調査被覆・権利・CRS／絶対Z・計算可能域を事前確認する。入力準備から3D構築、B1/B2出力までの市町村全域級の処理能力を、少なくとも一つの対象自治体で実証する。**行政区域、データ被覆、解析計算範囲、成果の有効範囲は別々に記録**し、被覆不足部分を勝手に補完・除外して「全域完了」としない。異なる条件を持つ別地域・ソースプロファイルでも移植性と拒否条件を検証する。3次メッシュ等の管理単位と解析のcontext/halo・最終cropを分離し、境界連続性、欠測、周辺遮蔽物、性能、ピークメモリ、失敗時の安全性を評価する。

**先行準備**：[データ一般化監査](OUEM_Data_Pipeline_Generalization_Audit_v0.1.md)のG01読取専用preflight、G02 Source-Hメンバー選択、G03 Terrain入力準備は候補。実施には個別レビューとPRが必要。[国立市2km調査](OUEM_Kunitachi_Data_Source_Preflight_v0.1.md)は有用な次地域の証拠だが、全域LoD2／Native/Standard/E2Eの成立ではない。

**出口の判定**：自治体全域級の対象境界に対し、**処理済み・データ不足／未評価・処理不能・対象外**の面積・位置を区別した成果と実行記録があり、少なくとも一つの自治体全域を対象とする処理と別条件の地域への移植性が検証されている。データ不足等によって評価できない区域が残る場合はその区域と理由を成果に明示し、評価可能域だけの結果を**自治体全域の定量評価達成**と呼ばない。2km preflightや数棟のPoCだけではこの出口を満たさない。未検証地域まで科学的精度を外挿しない。

**今は必須ではない**：全国を一括計算すること、全自治体でLoD2を必須とすること、任意のCRSや全事業者への無条件対応。

### M5 — 全国オンデマンド展開と社会実装

**中心：5モジュール横断、利用・運用設計。**

**必要な成果（提案）**：利用可能なデータの地域差・観測時点・権利・欠損を利用者が理解した上で、対象AOI／入力を選択し、検証済みの適用範囲内で3Dモデルと環境評価を再現できる。データ・モデル・OSS・教師データ・成果物の再配布／商用条件と、再現手順、資源見積り、変更・更新・異常時の扱い、地図表示・解釈上の限界を提示できる。自治体緑地計画やグリーンインフラ評価で試用・フィードバックを得る。

**出口の判定**：明示した地域・データ・指標・用途ごとの利用条件を満たして第三者が利用できること。**全国どこでも同一品質**や**すべての成果の科学的検証完了**を前提にしない。実証済みの用途と未検証用途を区別する。

## 4. 並行進行と依存関係

- **主要な成果の積み上げ（着手の強制的な直列順序ではない）**：M0の実証記録 → M1の樹冠3D → M2のB1/B2技術評価 → M3の科学的な主張の検証 → M4の広域再現性 → M5の適用用途。M3の参照調査やM4の小規模移植準備は前倒し可能であり、M4の技術実行にはM3の全面完了を要求しない。
- **準備は並行可能**：M1の進行中に、M3の参照データの候補調査、M4のG01–G03や国立市preflight、独立樹冠セグメンテーションのQA／学習を進めてよい。
- **成立・主張は別**：M2が未終了でもM3の調査は可能。M3で精度が未確認でもM4の限定技術移植は可能。ただしM5の利用可能とする範囲は、技術的証拠・科学的検証・権利・正式な設計判断に制約される。
- **選択的な技術経路**：VoxCityGMLを正式Adapterへ昇格させる判断やGSI点群からの詳細3D生成は、必要性・対象用途と証拠が整ったときに別途判断する。M1の無条件依存にはしない。

## 5. 現在の重点と最初の作業候補

**現在の重点：M1（樹冠）**。次の順で、原則として小さな設計・調査単位から始める。

1. **M1源情報の整理（既存Issue #178/#179/#181/#183）**：Metaの根拠付きCHM経路と、まだ実データ対応未確立のGSIセグメンテーション＋点高経路を分ける。合成fixtureのPASSをGSI実データ利用可能の証明にしない。新規取得・実処理は別承認。
2. **上位設計反映（Concept v0.3、PR #187反映済み）**：[Canopy Standard DRAFT](../OUEM_Standard_Canopy_v0.1_Draft.md)の水平根拠・状態／欠測・QAを更新し、[Issue #184](https://github.com/iwamoto31206803-max/open-urban-environment-model/issues/184)のポリゴン生成を**任意の派生出力試験**とする。正式Standard/Adapter契約の変更は別承認。
3. **M1合成の技術検証候補**：まずモデル判定／判定可能域／高さ有効性を独立して合成QAし、既存Height EnvelopeとVoxCityの数値経路を回帰保護する。オプションで4近傍の2D幾何export／往復QAを独立実施し、両試験を必須依存にしない。
4. **限定実データの技術照合候補**：別途明示承認後に固定64m×64m ROIのsource identity、共通入力旧／新経路のTREE voxel・建物優先・GridSpec・haloを同条件比較し証拠を記録。既存B1/B2/P1の保存証拠は改変しない。400×300m拡張は別判断。

**並行する候補**：M3は参照データ候補の初期一覧、M4はG01 read-only preflightの設計を必要に応じて進める。どちらもM1の閉鎖条件に無断追加しない。樹冠セグメンテーション・リポジトリの独立進行／QA承認は同リポジトリが所有し、OUEMへは明示された入力／出力／権利／評価済み性能のhandoffに限る。

## 6. 意思決定と運用ルール

1. **新しい作業は現行Mと成果を明示**する。該当しない場合は探索仮説か保守かを示し、進行中Mへ自動的に組み込まない。
2. **着手優先度**：(a) 現在の成果・未解決ブロッカー、(b) 現行OSS／既存OUEMを再利用できるか、(c) 最小PoCで仮説を検証できるか、(d) 先送り可能か、(e) 新たな依存・保守負担に見合うか、の順に評価する。
3. **完了を四軸に分ける**：実装／実行の技術的到達、科学的妥当性、正式Contract/Acceptance、利用・権利適格性。**ロードマップの「区切り」だけで他軸をPASSにしない**。未確認・保留・除外範囲を残す。
4. **段階の更新**：Userが目的・優先順位・重要な設計変更を決定。ChatGPTは選択肢・依存関係とレビュー、Codexは許可された実装／テスト／Draft PRを担当。大きな設計・科学的前提・正式契約・依存変更は個別承認する。
5. **参照負荷を抑える**：本書はマイルストーンと入口の正本。最新状態は[Canopy Current State](../status/CANOPY_CURRENT_STATE.md)／[Building Current State](../status/BUILDING_CURRENT_STATE.md)、科学的課題は[B1](OUEM_B1_Deferred_Validation_Backlog.md)／[B2](OUEM_B2_Deferred_Validation_Backlog.md)の既存Backlog、データ一般化は[一般化監査](OUEM_Data_Pipeline_Generalization_Audit_v0.1.md)、個別数値は元実験記録を参照する。毎回全履歴を読み直さない。
